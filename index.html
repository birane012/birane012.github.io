b012_data, Object–Relational Mapping, the Spring Boot way for flutter.

b012_data turns a plain Dart class into a persistent entity. CRUD statements, transactions, projections, file I/O — all generated from six simple conventions. No hand-written SQL. No repository boilerplate. Just Dart.

$ add to pubspec.yaml
b012_data: ^2.1.0

class Person {
  String? idPers;
  String? firstName;
  String? lastName;
  bool? sex;
  DateTime? dateOfBirth;

  // Primary key, foreign keys, nullability — all
  // declared as plain Dart getters.
  MapEntry<String, bool> get pKeyAuto =>
      const MapEntry('idPers', false);

  List<String> get notNulls =>
      ['firstName', 'lastName', 'sex', 'dateOfBirth'];

  Person([this.idPers, this.firstName, this.lastName,
          this.sex, this.dateOfBirth]);

  Map<String, dynamic> toMap() => {
    'idPers': idPers ?? ColumnType.String,
    'firstName': firstName ?? ColumnType.String,
    'lastName': lastName ?? ColumnType.String,
    'sex': sex ?? ColumnType.bool,
    'dateOfBirth': dateOfBirth ?? ColumnType.DateTime,
  };

  Person.fromMap(Map<String, Object?> json, {bool isInt = true}) {
    idPers = json['idPers'] as String?;
    firstName = json['firstName'] as String?;
    lastName = json['lastName'] as String?;
    sex = boolean(json['sex'], isInt: isInt);
    dateOfBirth = dateTime(json['dateOfBirth'] as String?);
  }

  Person fromMap(Map<String, Object?> json) => Person.fromMap(json);
}

§ 00 · Overview

Four ideas. One package.

b012_data keeps the surface area narrow on purpose: a class is the schema, an instance is the row, and two singletons do the rest.

[01]

Spring-style entities

Declare a primary key, non-null columns, uniques, checks, defaults and foreign keys as plain getters. DataAccess turns them into SQL.

pKeyAuto · notNulls · uniques · fKeys
[02]

Every CRUD, for free

Insert, bulk-insert, read-by-predicate, project single or multiple columns, update, delete, count — all typed, all generic, all transaction-aware.

insertObjet · get · getAll · update · delete
[03]

Six platforms, one API

Native sqflite on Android, iOS and macOS, sqflite_common_ffi on Linux and Windows, SQLite as WebAssembly in the browser — the same code everywhere.

Android · iOS · macOS · Linux · Windows · Web
[04]

Bytes on disk, metadata in SQLite

DiscData reads, writes, appends and resolves binary files as text, Base64, Uint8List or Flutter Image. Pair it with a row and you have media, solved.

readFileAs* · saveDataToDisc · getEntityFileOnDisc

§ 01 · Setup

Installation

Add the dependency, pull it in, and you are ready. The first access creates a default database named sqlf_easy.db.

Add the package to your pubspec.yaml:

dependencies:
  b012_data: ^2.1.0

Then run:

flutter pub get

2.1 requires Dart 3.12 and Flutter 3.44 or later (the current sqflite packages do); an application on an older Flutter keeps resolving 2.0.3.

Note — default database

The first access creates a default database named sqlf_easy.db in the application’s databases folder (see where your data lives). Use changeDB if you want another one.

Before calling any method that needs the documents directory (databasesPath, filesPath, …), make sure the Flutter bindings are initialized:

import 'disc_example.dart' as disc;
import 'sqlite_example.dart' as sqlite;

void main() async {
  WidgetsFlutterBinding.ensureInitialized();

  // SQLite CRUD walk-through (Person entity).
  await sqlite.runSqliteDemo();

  // File system / binary file walk-through (Images entity).
  await disc.runDiscDemo();
}
§ 02 · Conventions

Declaring an entity

An entity is a plain Dart class that exposes six well-known members. DataAccess reads them once, then generates every statement it needs.

  1. 1

    Primary key required

    A MapEntry whose key is the column name and whose value is true to use AUTOINCREMENT.

    MapEntry<String, bool> get pKeyAuto => const MapEntry('idPers', false);
  2. 2

    Constraints optional

    Non-nullable columns, uniques, check constraints, default values and foreign keys — each expressed as a getter.

    List<String> get notNulls  => ['firstName', 'lastName', 'sex', 'dateOfBirth'];
// List<String> get uniques => ['email'];
// Map<String, String> get checks   => {'email': 'length(email) > 4'};
// Map<String, String> get defaults => {'profession': 'NULL'};
// Map<String, List<String>> get fKeys => {'profession': ['Profession', 'idProf']};
  3. 3

    Unnamed constructor required

    Used by the package to instantiate an entity from the fromMap callback below.

    Person([this.idPers, this.firstName, this.lastName, this.sex, this.dateOfBirth]);
  4. 4

    Serialization toMap required

    For non-nullable fields the ColumnType fallback can be omitted — the value will never be null at insertion time.

    Map<String, dynamic> toMap() => {
  'idPers': idPers ?? ColumnType.String,
  'firstName': firstName ?? ColumnType.String,
  'lastName': lastName ?? ColumnType.String,
  'sex': sex ?? ColumnType.bool,
  'dateOfBirth': dateOfBirth ?? ColumnType.DateTime,
};
  5. 5

    Named fromMap constructor required

    Deserialization from a single SQLite row.

    Person.fromMap(Map<String, Object?> json, {bool isInt = true}) {
  idPers      = json['idPers']      as String?;
  firstName   = json['firstName']   as String?;
  lastName    = json['lastName']    as String?;
  sex         = boolean(json['sex'], isInt: isInt);
  dateOfBirth = dateTime(json['dateOfBirth'] as String?);
}
  6. 6

    Instance-side fromMap required

    Wraps the named constructor so generic getters can call it off any instance.

    Person fromMap(Map<String, Object?> json) => Person.fromMap(json);
§ 03 · Runtime

The CRUD walk-through

Every call below is the high-level equivalent of a Spring Data JPA repository method, driven exclusively through DataAccess.instance — no SQL string is ever written by hand.

Start by inspecting the schema that will be generated from your entity, then check whether the table already exists:

// Inspect the CREATE TABLE statement generated for the Person entity.
debugPrint('${DataAccess.instance.showCreateTable(Person())}\n\n');

// Does the Person table already exist in the database?
final bool personTableExists =
    await DataAccess.instance.checkIfEntityTableExists<Person>();
debugPrint('Person table exists? $personTableExists\n');
a. Create

Single row, then a whole list — inside one transaction.

insertObjet inserts a single entity. insertObjetList wraps a list of entities into a single atomic transaction. Both return a bool.

// CREATE — insert a single Person row.
final bool inserted = await DataAccess.instance.insertObjet(
  Person(newKey, 'KEBE', 'Birane', true, DateTime(2000, 8, 5)),
);

// CREATE (bulk) — insert several Persons inside a single transaction.
final bool personsListInserted =
    await DataAccess.instance.insertObjetList(<Person>[
  Person(newKey, 'Mbaye', 'Aliou', true, DateTime(1999, 5, 1)),
  Person(newKey, 'Cisse', 'Fatou', false, DateTime(2000, 7, 9)),
]);
b. Read

One row, many rows, a single column, or several columns.

Predicates are plain SQL strings passed as afterWhere. Booleans are converted to 0/1 for SQLite automatically, so sex = true is equivalent to sex = 1.

// READ — fetch a single row matching an SQL predicate.
final Person? birane = await DataAccess.instance.get<Person>(
  Person(),
  "firstName = 'Birane' AND lastName = 'KEBE'",
);

// READ — fetch every row.
final List<Person>? everyone =
    await DataAccess.instance.getAll<Person>(Person());

// READ — fetch rows matching a predicate.
final List<Person>? men = await DataAccess.instance.getAllSorted<Person>(
  Person(),
  'sex = true',
);

Projection — single column or a set of columns:

// READ (projection) — pull a single column across the whole table.
final List<String> firstNames =
    await DataAccess.instance.getAColumnFrom<String, Person>('firstName');

final List<String> womenFirstNames = await DataAccess.instance
    .getAColumnFrom<String, Person>('firstName', afterWhere: 'sex = false');

// READ (projection) — pull several columns at once.
final List<Map<String, Object?>> nameRows = await DataAccess.instance
    .getSomeColumnsFrom<Person>('firstName, lastName');

final List<Map<String, Object?>> womenNameRows =
    await DataAccess.instance.getSomeColumnsFrom<Person>(
  'firstName, lastName',
  afterWhere: 'sex = 0',
);
c. Update

Values follow the order columnsToUpdate + whereColumns.

Here: set firstName = 'developer' and lastName = '2022' where firstName = 'Birane' AND lastName = 'KEBE'.

final bool updated = await DataAccess.instance.updateSomeColumnsOf<Person>(
  <String>['firstName', 'lastName'],
  <String>['firstName', 'lastName'],
  <Object>['developer', '2022', 'Birane', 'KEBE'],
);
d. Delete & count

Remove rows matching a predicate, then count what’s left.

// DELETE — remove every row matching the predicate.
final bool deletedFatou = await DataAccess.instance.deleteObjet<Person>(
  "firstName = 'Fatou'",
);

// COUNT — total rows and filtered rows.
final int total = await DataAccess.instance.countElementsOf<Person>();
final int males = await DataAccess.instance.countElementsOf<Person>(
  afterWhere: 'sex = true',
);
Caution — destructive call

The following instruction drops the data of every table in sqlf_easy.db. Tables stay, rows are removed.

await DataAccess.instance.cleanAllTablesData();
§ 04 · Disk

Files on disk

The DiscData singleton reads, writes, appends and checks files. It returns text, Base64, Uint8List or a Flutter Image widget — and it can resolve a file name stored in SQLite back to raw bytes.

The pattern is simple: keep metadata (ids, timestamps, names) in SQLite, keep the binary blob on disk, and resolve one from the other with a single call.

class Images {
  String? imageID;
  String? imageName;
  DateTime? dateSave;
  DateTime? dateLastUpdate;

  MapEntry<String, bool> get pKeyAuto => const MapEntry('imageID', false);

  List<String> get notNulls =>
      const ['imageName', 'dateSave', 'dateLastUpdate'];

  Images([this.imageID, this.imageName, this.dateSave, this.dateLastUpdate]);

  Map<String, dynamic> toMap() => {
    'imageID':        imageID        ?? ColumnType.String,
    'imageName':      imageName      ?? ColumnType.String,
    'dateSave':       dateSave       ?? ColumnType.DateTime,
    'dateLastUpdate': dateLastUpdate ?? ColumnType.DateTime,
  };

  Images.fromMap(Map<String, Object?> json, {bool isInt = true}) {
    imageID        = json['imageID']   as String?;
    imageName      = json['imageName'] as String?;
    dateSave       = dateTime(json['dateSave']       as String?);
    dateLastUpdate = dateTime(json['dateLastUpdate'] as String?);
  }

  Images fromMap(Map<String, Object?> json) => Images.fromMap(json);
}
a. System paths

Three directories exposed by the package.

final String databasesPath = await DiscData.instance.databasesPath; // SQLite files
final String filesPath     = await DiscData.instance.filesPath;     // user files
final String rootPath      = await DiscData.instance.rootPath;      // documents dir
b. Write

One call writes text, Base64 or raw bytes.

// Save a text file into the default `files` directory.
final String? savedName = await DiscData.instance.saveDataToDisc(
  'contents of test.txt',
  DataType.text,
  takeThisName: 'test.txt',
);

// Save an Image (Base64) to the default `files` directory.
final String? testImage = await DiscData.instance.saveDataToDisc(
  testImageAsBase64,
  DataType.base64,
  takeThisName: 'testImage.png',
);

// Store a matching metadata row for that image.
final bool imageRecordCreated = await DataAccess.instance.insertObjet(
  Images('img0001', 'testImage.png', DateTime.now(), DateTime.now()),
);
c. Read

As a string, Base64, bytes — or a Flutter widget.

// Exists?
final bool exists = await DiscData.instance.checkFileExists(fileName: 'test.txt');

// As a UTF-8 string.
final String? asString = await DiscData.instance.readFileAsString(fileName: 'test.txt');

// As Base64 — handy to ship blobs over JSON.
final String? asBase64 = await DiscData.instance.readFileAsBase64(fileName: 'testImage.png');

// As raw bytes — images, audio, video, PDFs, anything binary.
final Uint8List? asBytes = await DiscData.instance.readFileAsBytes(fileName: 'testImage.png');

// Straight into a Flutter `Image` widget.
final Image? asImage = await DiscData.instance.getImageFromDisc(imageName: 'testImage.png');
d. Database-backed resolution

Metadata in SQLite, blobs on disk, one call to bind them.

Given a table Images with a column imageName that holds a file name on disk, fetch the raw bytes of the row where imageID = 'img0001':

final Uint8List? entityBytes = await DiscData.instance
    .getEntityFileOnDisc<Uint8List, Images>(
        'imageName', 'imageID', 'img0001');
§ 2.1 · Opt-in

What’s new in 2.1, in detail

2.1 hardens the package without changing how you use it: everything of 2.0.3 keeps working unchanged, and each addition below is opt-in. The full list is in the changelog.

a. Security

Bound values: never build afterWhere from user input.

afterWhere is inserted as is after WHERE (that is what lets you write ORDER BY and LIMIT in it). Put ? placeholders in it and pass the values in whereArgs instead — booleans and dates are bound exactly as b012_data stores them.

final Person? p = await DataAccess.instance.get<Person>(
  Person(),
  'lastName = ? AND sex = ?',
  [userInput, true],
);
final int n = await DataAccess.instance.countElementsOf<Person>(
  afterWhere: 'dateOfBirth >= ?',
  whereArgs: [DateTime(2000)],
);

Every afterWhere method accepts whereArgs (positional after afterWhere for get, getAllSorted and deleteObjet, named otherwise). The queries the package builds itself (getLogin, checkIfTableExists, getEntityFileOnDisc, …) always bind their values. Table and column names that are SQL keywords (order, group, …) are quoted for you; in your own afterWhere text, quote them yourself ('"group" = ?'). whereMcop accepts only AND and OR.

b. Errors

Strict mode, or just be told.

DataAccess.instance.strict = true;          // throw the real error
DataAccess.instance.onError = (e, s) => log(e); // or just be told

With strict, a failing insert or update throws the real DatabaseException instead of returning false; “nothing found” is still null or []. Without it, every error turned into false or [] is still printed with debugPrint and also passed to onError.

c. Transactions

Everything or nothing.

await DataAccess.instance.transaction(() async {
  await DataAccess.instance.insertObjet(order);
  await DataAccess.instance.updateSomeColumnsOf<Stock>(['qty'], ['id'], [qty - 1, id]);
}); // everything or nothing

Every DataAccess method called inside takes part in the transaction; a transaction started inside a transaction joins it. Inside a transaction a failing method throws (even outside strict mode) instead of returning false, so that everything is rolled back. Outside a transaction, insertObjetList keeps its 2.0.3 behaviour (rows before a failing one are kept).

d. Replace, keys, indexes

One parameter, three new getters.

await DataAccess.instance.insertObjet(person, orReplace: true); // INSERT OR REPLACE

New optional entity getters — pKeys declares a composite primary key, in place of pKeyAuto:

List<String> get pKeys => ['maintenanceId', 'technicianId'];   // composite key
Map<String, List<String>> get indexes => {'assignment_trade': ['trade']};
Map<String, List<String>> get uniqueIndexes => {'one_trade': ['maintenanceId', 'trade']};

Indexes are created when missing, also on an existing table.

e. Stable table names

Register the entities whose name must not move.

A table is named after its class. Obfuscated builds (and web release builds) change class names, so register the entities whose table name must stay the same:

DataAccess.instance.registerEntity<Person>('person');

Every method follows the registration, including the ones that only receive the type (countElementsOf<Person>()). In a browser, registration is required.

f. Schema evolution

New columns, versioned migrations.

DataAccess.instance.autoAddColumns = true; // new entity columns are added
DataAccess.instance.migrations = {
  2: () => DataAccess.instance.rawExecute('UPDATE person SET sex = 0 WHERE sex IS NULL'),
  3: () async { /* ... */ },
};

With autoAddColumns (off by default), a column added to an entity is added to its table (ALTER TABLE … ADD COLUMN); columns are never dropped or renamed. Migrations run once each when the database opens, in order, each in its own transaction that sets PRAGMA user_version; a failing step is rolled back and makes the opening fail. Set both before the first access.

g. Queries

Paged, sorted, bound — or raw SQL.

final List<Person> page = await DataAccess.instance.query<Person>(
  Person(),
  where: 'sex = ?',
  whereArgs: [true],
  orderBy: 'lastName',
  limit: 20,
  offset: 40,
); // [] when nothing matches
final rows = await DataAccess.instance.rawQuery('SELECT ... WHERE x = ?', [x]);
final people = await DataAccess.instance.rawQueryAs<Person>(Person(), 'SELECT ...');
final changed = await DataAccess.instance.rawExecute('UPDATE ... WHERE id = ?', [id]);

orderBy is inserted as is, like afterWhere: never from user input. rawExecute returns the number of rows the statement changed.

h. Foreign keys

Declared, and now enforced on demand.

fKeys were declared but never enforced. Set enforceForeignKeys before the first access to enforce them (PRAGMA foreign_keys = ON). It is off by default, because enforcing them could break an application that inserts a child before its parent.

DataAccess.instance.enforceForeignKeys = true;
i. Web

The same API, in a browser.

dart run b012_data:setup_web   # puts sqlite3mc.wasm and sqlite3.wasm in web/
  • SQLite runs as WebAssembly (sqlite3mc.wasm by default; set DataAccess.instance.webSqliteWasmUri to use another module). Databases and DiscData files live in IndexedDB; persistent storage is requested.
  • Every write is stored in IndexedDB before its future completes.
  • One tab at a time: a second tab opening the same database gets a clear StateError instead of a copy that would overwrite the first. This needs the Web Locks API, available on https and localhost.
  • Entities must be registered (registerEntity).
  • DataAccess.db and openDB (sqflite objects) are not available; DiscData.getFile returns null (there is no file system).
  • A browser can still erase site data when the user clears it.
j. Encryption

Against a lost or stolen device.

The database and the files saved by name can be encrypted with SQLite3MultipleCiphers (MIT licence). Choose this engine in your application’s pubspec.yaml (in a browser, setup_web already provides sqlite3mc.wasm):

hooks:
  user_defines:
    sqlite3:
      source: sqlite3mc
await DataAccess.instance.useEncryptionKey(key);      // before the first access
await DataAccess.instance.encryptDatabase(key);       // encrypt an existing plaintext database in place
await DataAccess.instance.changeEncryptionKey(newKey);
  • A new database is created encrypted; a wrong key throws a StateError.
  • The engine is checked first: if it does not encrypt, a StateError says what to add to pubspec.yaml. A database is never created in plaintext by mistake.
  • A key given for an existing plaintext database is refused (use encryptDatabase); an encrypted database is never opened without its key.
  • Files saved by name with DiscData are encrypted (AES-256-GCM) with a random key kept inside the encrypted database, so changing the database key rewrites no file. Files written at an explicit path stay plain unless saveDataToDisc(..., encrypt: true).
  • encryptDatabase encrypts the files DiscData saved by name since 2.1 and the names you pass in alsoFiles; nothing else in the files folder is touched.
  • On Android and iOS an encrypted database goes through the engine bundled by package:sqlite3, not the system SQLite.
  • b012_data never stores the key: your application provides it at each start. On a device, keep a random key in the system vault (Keystore, Keychain, Windows data protection); in a browser there is no vault, so the key must come from something the user types.
k. Where your data lives

Windows and Linux: one folder per application. Everywhere: files written safely.

  • Android, iOS, macOS: exactly as in 2.0.3.
  • Windows, Linux: 2.0.3 created the database under the current directory (.dart_tool/sqflite_common_ffi/databases), so launching the application from another folder opened another database. 2.1 keeps a new installation’s databases, dbName and files in the application support folder. A database left by 2.0.3 is found and kept where it is (its absolute path is recorded), so nothing disappears.
  • changeDB creates the folder it needs.
  • Files are read and written asynchronously. A file is written to a temporary file, flushed, then renamed over the target: a reader never sees half of it.
  • A file name can no longer point outside filesPath ('../x' throws an ArgumentError); explicit absolute paths work as before.
l. Also in 2.1

Robustness, requirements, tests.

  • One opening shared by concurrent first accesses; table creations serialized.
  • Failing entity getters are reported. A constant checks map no longer crashes table creation when the entity has a boolean column.
  • Requires Dart 3.12 / Flutter 3.44 (current sqflite); older Flutter versions keep resolving 2.0.3.
  • The package now has 98 tests, plus a browser check (tool/web_check).
  • Tested for 2.1 on Windows (unit tests, real SQLite3MultipleCiphers), in Chrome (the check application in tool/web_check) and on an Android emulator. iOS, macOS and Linux share the same code paths.
§ 05 · Edge cases

Things to know

Three subtleties that save debugging time later.

01

Missing-table exceptions

Most entity-oriented methods throw DatabaseException('no such table: …') when the underlying table does not exist. The exceptions are updateWholeObject, updateSomeColumnsOf, getAColumnFromWithTableName and getAColumnFrom, which catch the error and only log it via debugPrint (and onError) — unless strict is set. Wrap the other methods in try/catch if you are not sure the table already exists.

02

Dart map vs. SQLite-ready map

insertObjet and insertObjetList internally convert your entity map using mapToUse(entity.toMap()). Call mapToUse(entity.toMap(), forDB: false) yourself when you want a plain Dart map (for JSON serialization or display) instead of an SQLite-ready one.

03

afterWhere is inserted as is

Never build an afterWhere text from user input: put ? placeholders in it and pass the values in whereArgs (see bound values).
